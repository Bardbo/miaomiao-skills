# Gate 检查清单

出片前必过六道 Gate。任一不通过则打回重写，**不允许"先出片再补检查"**。

其中 G1 / G2 / G4 可用 `scripts/check_gates.py` 做静态硬校验。

> **为什么必须用脚本**：写在提示词里的规则会被 LLM 绕过。写在脚本里的不会。

---

## G1 溯源

**检查**：定制版每个 bullet 能否追溯到母版的条目 ID？

**方法**：
```bash
python scripts/check_gates.py --target targets/<岗位目录>
```

**失败处理**：追不到母版 ID 的 bullet = L4 违规。
→ 不要删除了事。把它作为新条目加进母版，标记 `evidence: pending`，写入 `gaps`。

---

## G2 证据状态

**检查**：

| 检查项 | 规则 |
|---|---|
| `evidence: inferred` 的条目 | **禁止出现在成品中** |
| `evidence: pending` 的条目 | 不得写成确定语气，须标 `【待补】` |
| `strength: strong` 且 `evidence != verified` | 强主张配弱证据，必须降级 |

**降级规则**：

| 原表述 | 降级为 |
|---|---|
| 主导 | 参与 / 负责其中 X 部分 |
| 从 0 到 1 搭建 | 参与搭建 |
| 全面负责 | 负责 |
| 精通 | 熟悉 / 了解 |

**渲染表现**：`pending` 条目在预览中标灰并注明原因。

---

## G3 覆盖度

**检查**：P1 关键词命中率。

- 命中率 ≥ 70%：通过
- 命中率 50-70%：警告，未命中的写进 `gaps`
- 命中率 < 50%：**告知用户"你的经历与该岗位匹配度偏低"**，询问是否仍要投递

第三档很重要——**匹配度低时，诚实地告诉用户，比硬凑一份简历更有价值**。

---

## G4 去 AI 味

**检查**：
1. 扫描 `assets/forbidden_terms.txt` 中的禁用词
2. 检查 AI 味句式（见 `rewrite-rules.md`）
3. 检查动词与 `strength` 是否匹配

**失败处理**：强制改写，不要只是"建议"。

---

## G5 反向面试（最有效的一道）

**做法**：假设自己是面试官，对**每个** bullet 追问三层。

```
bullet: 将归因延迟从 24 小时降至 5 分钟
追问 1: 为什么原来是 24 小时？
追问 2: 用了什么方案压到 5 分钟？
追问 3: 压到 5 分钟牺牲了什么？准确性怎么保证？
```

**判定**：
- 三层都能基于母版信息答上来 → 通过
- 有一层答不上 → 降级（去掉无法支撑的部分）
- 有两层答不上 → **删除该 bullet**

---

### ⚠ 判定的前提：先分清「编造」和「未采集」（执行经验，重要）

**原规则有缺陷**——它只说"答不上就删"，但答不上有两种截然不同的原因：

| 类型 | 特征 | 处理 |
|---|---|---|
| **编造 / 注水** | 说不出具体的技术名词、工具名、场景 | **删除**，无商量 |
| **真实但信息未采集** | 能说出具体技术名词，只是 result / difficulty 字段空着 | **标记待补，不删** |

**区分方法**：追问「你用的什么工具/算法/框架？」
答得出来 → 大概率是真实经历，只是细节没采集；答不出 → 可疑。

为什么必须区分：如果对"未采集"也执行删除，简历会越做越空，
最后只剩一堆安全但无用的废话——**过度执行的 G5 比不做 G5 更有害**。
真实的经历应该被补强，而不是被删掉。

典型场景：用户给了一份旧简历，只写了"负责 XX 算法的开发与仿真"。
追问答不上细节，但技术名词具体可信 → 属于未采集，应补强而非删除。

---

### 涉密经历：不适用 G5，改用「收敛表述」原则

涉密项目不能走标准反向面试——面试官追问三层、你三次都回"涉内部系统，不便展开"，
场面难看，还会让人怀疑是否真有内容。

**正确做法不是准备挡箭牌，而是让表述本身不引发追问。**

- ✅ 安全：「参与算法模型构建与数据分析」——听起来就是常规工作，没有深挖钩子
- ❌ 危险：「构建了多源数据融合的智能分析模型」→ 什么模型？什么数据？
- ❌ 危险：「支撑多起案件侦破」→ 直接涉密，且必然被追问细节

判断标准：**这句话会不会让人想追问"怎么做的"？** 会 → 收敛它。

---

### 强主张 + 无细节 = 最高风险组合

「独立负责」「主导」「从 0 到 1」这类强主张，配上答不上来的三层细节，
**比不写更糟**——面试官会判定你在夸大，而非只是记得不清。

处理：**要么补细节，要么降级措辞，二选一。不允许"强主张 + 空细节"出片。**

降级示例：
- ❌ 独立负责垃圾询识别算法的开发、部署与运维
- ✅ 负责垃圾询盘识别算法的开发与部署，参与数据集构建与模型微调
  （把强主张拆成几块，给自己留回旋余地——"这块是同事负责的"是合法回答）

---

**为什么最有效**：结果可以注水，追问链很难编。这道 Gate 能筛掉绝大多数注水和 AI 编造的内容，比任何"去 AI 味"规则都更能保证简历的真实强度。

**执行方式**：改完简历后立刻做，不要等用户来问。
产出一份追问报告随成品交付——让用户看到每条 bullet 在面试里会被问什么，比让他自己发现更有价值。

---

## G6 版式

**检查**：
- 渲染后页数不超过 `preferences.max_pages`
- 无孤立标题、无跨页断行
- 联系方式完整、可点击（邮箱 / 电话 / 链接）
- 字体统一，无乱码

**工具**：`html-review` 技能可做版式质量检查。

---

## 执行顺序与短路

```
G1 溯源 → G2 证据 → G3 覆盖 → G4 去 AI 味 → G5 反向面试 → G6 版式
```

G1 不通过直接打回（后续检查无意义）。
G2 不通过打回（内容真实性有问题）。
G3/G4 可边改边过。
G5 是最耗时的，但**不能跳过**。

---

## 输出

Gate 全部通过后，生成检查报告随成品交付：

```markdown
## 质量检查
- G1 溯源：12 条 bullet 全部可追溯 ✅
- G2 证据：2 条降级（exp-007-a1 主导→参与），1 条标记待补
- G3 覆盖：P1 命中 4/5，未命中「K8s 运维」已列入待补
- G4 AI 味：改写 3 处（"赋能""闭环"）
- G5 追问：删除 1 条 bullet（追问两层答不上）
- G6 版式：1 页，通过
```

让用户看到你做了什么检查，比让他自己去发现更可信。

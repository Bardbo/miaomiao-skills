# 内容质量人审清单（Phase 4.5）

## 为什么要单独这一层

G1–G6（Gate 链）覆盖的是**结构 / 证据 / 覆盖 / 去 AI 味 / 版式**。它们能拦住"编造、漏源、
AI 味、版式崩"，但拦不住"**内容差**"——也就是**闸门全绿、成稿却很 low** 的情形。

实证（2026-09-22，示例客户 → 某科技公司副总经理岗）：出片时 `GATES_EXIT=0`（六道全过），
用户看后判"成品很差"——开源选项太弱、写了 star、写了「涉密项目」、缺乏对口含金量。
其中 star / 涉密 现已由渲染器 `_os_fmt` + G4 词表兜底（不会再出现），但**开源对口度、
量化率、摘要呼应 JD、整体观感**这几类"内容质量"问题，是自动化闸门够不到的——
必须有一道独立的**人审**来补。

**定位**：机械可查的部分，AI 出片前自动扫一遍；判断类部分，必须交回用户过目。
两者都过，才进 Phase 5 出片。

> 与「low 感」禁用清单（`rewrite-rules.md`）的关系：那张清单管的是**写法层面的 low**
> （技能后跟"熟悉"、荣誉只剩"优秀团员"、单列工具名……），渲染器/校验器已强制。
> 本清单管的是**内容层面的 low**——写法是职业的，但"选了弱项目 / 没呼应 JD / 读起来没东西可放"。

## 触发时机

Phase 4 Gate 链**通过之后**、Phase 5 出片**之前**。每次出片（含回流后重新出片）都要过一遍。

## 一、机械自检（AI 读 final HTML 自动判，输出 PASS / FAIL）

| 编号 | 检查 | 判据 | 失败动作 |
|---|---|---|---|
| **C1 开源不写 star** | 成稿 opensource 段是否出现 ★ 或 "star" / 数字背书 | 必须**无** | 渲染器已兜底（`_os_fmt` 不渲染 stars）；若出现是回归 bug，修 `render_resume.py` |
| **C2 涉密零字样** | 成稿是否含「涉密项目」「机密项目（写内容）」等 | 「涉密项目」四字必须**无**；可留「算法建模与数据分析」等能力描述 | 改母版 evidence_note 之外的正文，去掉字样（涉密红线 risk-002 仍适用：不写数据源/案件类型/系统名/真实数据量） |
| **C3 开源筛强留弱** | 展示的 opensource 条数是否 ≤ 该岗位合理上限（默认 ≤ 4–6）；弱的/无关的是否已进 `hidden_opensource`；描述是否"职业产出腔"（含支撑/产出/提升等结果动词）而非"折腾笔记腔" | 条数合理 + 仅留最对口、最有含金量 + 描述有产出导向 | 调整 `hidden_opensource`，重写弱条目描述（基于真实已有功能，不编造） |
| **C4 量化补全** | 成稿 `result` 全空的比例；是否至少用定性（规模/范围/主导-参与）替代硬数字 | 关键 bullet 不应全空；能定性就不留白 | 补定性表述（**不编数字**；缺的标 `pending` 进 gaps） |
| **C5 摘要呼应 JD** | 若启用 `summary`，是否把最硬的 2–3 条（呼应 JD P1）摆到首屏 | 摘要句含 JD P1 关键词且是本人最强事实 | 重写 `summary_text` |
| **C6 去 AI 味（超出词表）** | 读起来是否像人写的职业简历：有无长句堆砌、空话排比、"赋能/助力/闭环"等残留 | G4 已过则基本 OK；再扫一遍语气 | 改写 |

> C1 / C2 已下沉为渲染器 + G4 的硬兜底，这里列为自检项是为了**防回归**（哪天改坏能立刻发现），
> 不是指望每次都靠人盯。C3–C6 是当前闸门真正够不到的部分，是这一层的主战场。

## 二、人审提示（AI 给不出判断，必须让用户过目）

AI 出片前，把下面 4 问作为确认问题抛给用户（走 AskUserQuestion 或普通提问皆可）。
用户任一项说"不对"，打回改，**不改不进 Phase 5**。

| 编号 | 问题（给用户） | 为什么必须人审 |
|---|---|---|
| **H1 内容对口度** | "每条经历/技能，你看了觉得确实是这个岗位要的活吗？有没有为了凑数放了一条其实不相关的？" | 闸门只测关键词命中，测不出"命中的那条其实不相关" |
| **H2 含金量诚实度** | "有没有哪条让你觉得'这写得好听但其实我也就那么回事'？这种最容易被追问崩。" | 虚高 bullet 是面试崩盘源；闸门不判"你到底行不行" |
| **H3 市场匹配** | "这份投这个岗位，你真实竞争力如何？缺口（如副高/管理经验）如实保留了吗？" | 缺口只能如实进 `gaps`，不能靠包装掩盖 |
| **H4 整体观感** | "第一眼读，像'会写简历的人写的'，还是'没东西可放'？" | 直接对应「low 感」禁用清单的判定口诀 |

## 三、输出形态（AI 出片前给出的报告）

```
【内容质量人审 Phase 4.5】
机械自检：C1 ✅ C2 ✅ C3 ⚠️(开源 6 条偏多，建议隐 2 条最弱的)
          C4 ⚠️(3 条关键 bullet 全空，已补定性表述) C5 ✅ C6 ✅
人审待确认：H1–H4 四问已抛给用户 → 等裁决
结论：机械项 2 处待修 + 人审未裁决 → 暂不进 Phase 5 出片
```

机械项全 PASS 且人审用户签字后，才进 Phase 5。

## 四、与 Gate 链的关系

- **Gate 链（G1–G6）** = 自动化硬校验，不过打回。
- **Phase 4.5** = 内容质量人审，堵 Gate 覆盖不到的"内容差"。两者**正交**，Phase 4.5 在 Gate 之后。
- 不要试图把 H1–H4 写进脚本——那是用户的主观判断，脚本替代不了。
  C1–C6 里能机械判的才进脚本兜底（star/涉密 已在 render + G4 实现）。

# 模拟面试出题手册（Phase 7 详细规则）

> SKILL.md 的 Phase 7 只讲触发时机与交互约定，本题库是**出题的具体玩法**：
> 题源、三类题型模板、配比、输出格式、陪练反馈、禁止清单。
> 核心立场与全 skill 一致——**只筛选、不编造**：题目必须能在成稿 / JD 里找到出处。

---

## 一、出题总原则

- **题源唯一**：只从「成稿 HTML / 母版 YAML / JD 文本」里**已有**的事实出题。
- **每条题必须能回指成稿某一段**（给"出处"锚点），让用户和 AI 都能核对。
- **禁止编造**：不凭空造一段经历来出题；不把 `pending` / 推断填充当成既定事实出题而不提示。
- **不修改成稿**：模拟面试是练手，不是改简历；要补内容走 Phase 6 回流。

---

## 二、三类题型与出题模板

### 1. 行为类（STAR）

针对成稿里的**成就卡**（带数字结果的经历块）。考察候选人对自己写下的结果是否真懂、能经追问。

- **出题角度**：情境(S) / 任务(T) / 行动(A) / 结果(R) / 如果重来。
- **模板**（按成稿字段填空）：
  - "你在『{成就卡标题}』里提到 {具体数字/动作}，当时是什么情境逼你这么做？"
  - "这个 {数字} 是怎么算出来的？口径和基准是什么？"
  - "如果重来一次，哪一步你会提前做 / 换做法？"
- **例**：成稿"建立保险浮存金结构，年末浮存金约 1,760 亿" →
  "你如何说服团队接受低成本负债结构？浮存金成本比行业低多少？"

### 2. 技术 / 专业类

针对 **JD 的 P1 硬要求 + 成稿技能段**。考察落地能力，不是背概念。

- **出题角度**：落地细节、边界条件、失败案例、权衡取舍。
- **模板**：
  - "JD 要求 {P1 关键词}，你在成稿里写了 {对应技能}，具体怎么落地？"
  - "遇到 {边界场景} 时你的处理框架是？"
- **例**：JD 要"组合构建" → "你的仓位管理框架怎么定回撤阈值？单票上限怎么设？"

### 3. 反向压力类（来自 G5 反向面试）

把 **Gate 链的薄弱点**变成追问——成稿里 `pending` / 推断填充 / G3 匹配缺口 / G5 扛不住追问的条目，正是面试官会深挖的软肋。

- **来源**：成稿 `pending` / 推断填充 / G3 未命中 P1 / G5 软项。
- **模板**：
  - "成稿里『{条目}』还是 pending / 推断，能展开讲讲实际做过什么吗？"
  - "JD 的 P1『{词}』你成稿没举证，实际经验到什么程度？"
- **例**：成稿"Python"是推断填充且未举证 → "给一段你用 Python 做过的回测 / 分析代码思路。"

---

## 三、默认配比与数量

- **默认 3–5 题**：行为 2 + 技术 1–2 + 反向 1。
- 用户可要更多，或"只要行为类 / 只要技术类 / 只要反向压力"。
- **无 JD 时**：跳过"技术类对齐 JD"那部分，只出行为类（基于成就卡）+ 基于成稿技能段的专业题；反向压力类标注"无 JD 可对照，按成稿自身薄弱点出题"。

---

## 四、每题输出格式

```
【行为题 1】<问题>
  考察点：<想验证的能力>
  成稿锚点：<成稿里已有的事实，作为理想回答的支撑——不替用户编答案>
  出处：对应成稿『{块标题}』第 N 条
```

"成稿锚点"只列**已有事实**，是理想回答的"及格线"；用户答完由 AI 对照给反馈，不预先写标准答案。

---

## 五、陪练反馈模式（用户答完后）

对照成稿事实给反馈，三档定性：

- **有支撑**：回答里的点成稿里确实有 → 肯定，提示可放心讲。
- **在发挥**：成稿没写、用户自己补的 → 提示"这点成稿没体现，面试时若要说需确保能经住追问，否则别主动提"。
- **与 JD 对齐**：指出哪些点正好命中 JD 的 P1，哪些 P1 还没被回答覆盖（对应缺口正是面试前该补的）。

---

## 六、禁止清单

- ❌ 不编简历里没有的项目、数字、公司、职位。
- ❌ 不把 `pending` / 推断填充当成既定事实出题而不加"这块成稿还是空白 / 推断"的提示。
- ❌ 不修改成稿（改内容走 Phase 6 回流）。
- ❌ 不替用户写"标准答案"——只给锚点和反馈，回答是用户自己的。

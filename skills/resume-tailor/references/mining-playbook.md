# 素材挖掘手册

> 配套 `scripts/density.py`（篇幅诊断）与 `scripts/polish.py`（bullet 评级）。
> 三者构成闭环：**density 说还差多少 → 本手册说去问什么 → polish 说问回来后怎么改写**。

---

## 0. 这份手册为什么存在

**用户不会主动给你写好简历的素材。** 这不是配合度问题，是认知问题：

1. **他们不知道什么值钱。** 一个会计会说"我每个月做账"，不会说"我把月结从 3 天压到 1 天"——
   因为他不知道后者才是简历要的东西。
2. **他们低估自己。** "这个不算什么，就是帮同事拉了个数"——
   而那恰恰是唯一能证明他能独立干活的一条。
3. **他们高估熟悉度。** 干了五年的事，默认"这不是人人都知道吗"，于是一笔带过。

所以**"充分引导"不是多问几句，是要有针对性的提问弹药**。通用问题（"你取得了什么成绩？"）
问出来的是通用废话（"提升了效率"）。

**本手册的立场：提问的质量决定成稿的上限，改写只能决定下限。**
一条只有"负责 XX 工作"的 bullet，再怎么润色也是"负责 XX 工作"；
而一条有数字、有边界、有难点的素材，即便原话很土，也能改成人话里的强 bullet。

## 1. 素材量门槛：先知道够不够，再谈怎么问

**在追问之前先算账。** 盲目追问会问到用户烦，而且不知道何时该停。

先跑 `python scripts/density.py --person <姓名>`，拿到的数字对照下表：

| profile | 目标页数 | 经历段数 | bullet 总数 | 技能分组 | 必备段落 |
|---|---|---|---|---|---|
| `campus` 校招 | 1 页 | 1–2（含实习/项目/竞赛） | **6–9** | 3–4 组 | 教育、主修课程、校园经历 |
| `junior` 初级 | 1 页 | 1–2 | **6–9** | 3–4 组 | 技能、证书 |
| `experienced` 社招 | 1 页 | 2–3 | **7–10** | 3–5 组 | 技能、证书 |
| `expert` 资深 | 1–2 页 | 3–4 | **8–12** | 3–5 组 | 技能、证书、论文/专利 |

**换算基准**（由 density 的容量模型得出）：
- A4 一页正文区 = 42 行，扣掉抬头（约 3.5 行）与页脚（约 2 行），**净 36 行**
- 一条理想 bullet ≈ **2 行 ≈ 90 字**（一句话说完"做了什么 + 怎么做的 + 结果"）
- 段标题 + 经历标题 ≈ 每段 3 行 → 3 段 = 9 行
- 所以：**36 行 ≈ 9 行结构 + 27 行内容 ≈ 13 条 bullet 的位置**
  但 bullet 平均只有 1.5 行，且技能/证书/教育要占 8–10 行 → **实际需要 7–10 条**

**低于门槛 60% 时，不要靠润色救。** 那是素材问题，回到本手册第 2、3 节。

## 2. 线索追猎法：从一句话里挖出一整段

用户的原话里埋着线索词，**每个线索词后面都藏着 2–3 个可问的维度**。
不要问"还有什么要补充的吗"（答：没有），要抓词追问。

### 操作模板

```
用户说：「我[动词]了[对象]，用[方法]」
          ↓ ↓ ↓
     每个槽位都是追问入口
```

| 槽位 | 追问维度 | 话术 |
|---|---|---|
| **动词** | 是执行还是主导？是一个人做的吗？ | "这件事是你一个人从头跟到尾的，还是团队里你负责其中一块？" |
| **对象** | 有多大？多少？多久？ | "这个[对象]的量级大概是多少？多少条/多少人/多少钱？" |
| **方法** | 为什么用这个？跟原来比呢？ | "在你们用这个办法之前，是怎么做的？" |
| **缺失：结果** | 做完了然后呢？ | "做完之后，什么变了？" |
| **缺失：影响** | 谁在用？还在用吗？ | "现在还有人在用你做的这个吗？几个人？" |
| **缺失：难点** | 卡在哪？ | "最让你头疼的是哪一步？" |

### 实例

> 用户："我就是做一些数据处理的工作。"

抓词：**数据处理**。

1. "什么数据？"（对象规模）→ 销售数据 / 生产数据 / 用户行为
2. "多久搞一次？"（频次）→ 每天 / 每月 / 临时
3. "量有多大？"（规模）→ 几万行 / 几个 G
4. "之前谁在做？怎么做？"（对比基线）→ 人工 Excel / 没人做
5. "你做完后给谁用？"（影响）→ 给领导看 / 给业务同事用
6. "现在还是你在做吗？"（可持续性）→ 做成模板了，同事自己刷新

**六问下来，"做一些数据处理的工作"能变成两条有量化、有影响的 bullet。**
这就是挖掘的全部秘密——不是问更多问题，是问对了维度。

## 3. 职业族挖掘清单

**通用问题问不出行业素材。** 以下是按职业族准备的弹药，选用户对应的那一族，逐条试探。
**一次只问一条**，用户答不上就换下一条，不要连珠炮。

### 3.1 技术研发（研发 / 算法 / 测试 / 运维 / 数据）

| 维度 | 追问 |
|---|---|
| 规模 | 多少 QPS / DAU / 数据量 / 服务数 / 代码行数？ |
| 前后对比 | 延迟、耗时、资源占用从多少变多少？ |
| 线上事故 | 处理过几次线上故障？最严重一次影响多久、多少人？怎么定位的？ |
| 技术选型 | 为什么选 A 不选 B？有没有方案被推翻过？ |
| 复用范围 | 你做的东西谁在用？团队 / 部门 / 全公司？ |
| 交接与传承 | 有没有人接手你的东西？你写了文档吗？带过人吗？ |
| 个人边界 | 团队几人，你负责哪一块？代码是你提交的吗？ |
| 难点 | 最卡的是哪一步？不中断服务做迁移？性能调优的瓶颈在哪？ |

### 3.2 销售 / 商务 / BD

| 维度 | 追问 |
|---|---|
| 业绩 | 年度/季度完成多少？完成率？团队几个人里排第几？ |
| 客户 | 新签几家？存量维护几家？最大一单多少？ |
| 回款 | 回款率多少？账期多长？有没有清过坏账？ |
| 从 0 到 1 | 开拓过新区域/新行业/新渠道吗？ |
| 最难的单 | 哪单卡得最久？怎么破的？ |
| 方法论 | 有没有沉淀话术/SOP？带过几个新人？ |
| 协作 | 跟交付/产品/法务怎么配合？有没有你推动解决的卡点？ |

### 3.3 财务 / 会计

| 维度 | 追问 |
|---|---|
| 核算规模 | 管几个主体？月均多少凭证？资产规模多大？ |
| 周期 | 月结几天完成？原来几天？ |
| 税务 | 做过汇算清缴吗？有没有做过合规的税筹安排？ |
| 工具化 | 做过哪些模板/脚本？谁在用？几个人在用？ |
| 审计 | 配合过几次审计？有没有发现过重大差错？ |
| 制度 | 写过制度或流程吗？落地了吗？ |
| 跨部门 | 跟业务/仓库/采购的对账机制是谁建的？ |

> **财务岗最容易被漏掉的金矿**：自己做的 Excel 模板、自动化的报表脚本。
> 会计普遍觉得"这不就是个工作表吗"，但它恰恰是"能独立交付工具"的证据——
> 这比"熟悉 Excel"强一个数量级。

### 3.4 人事 / 行政 / 文秘

| 维度 | 追问 |
|---|---|
| 招聘 | 年招聘量多少？到岗率？平均到岗周期从多久压到多久？ |
| 渠道成本 | 开拓过什么渠道？人均招聘成本变化？ |
| 薪酬绩效 | 做过几次调薪/绩效方案？覆盖多少人？ |
| 员工关系 | 处理过几起劳动争议？结果如何？ |
| 培训 | 组织过几场？覆盖多少人次？ |
| 制度 | 建过哪些制度/流程/台账体系？ |
| 成本 | 行政集采/议价省了多少？ |
| 活动 | 组织过什么规模的活动？多少人次？预算多少？ |
| 应急 | 处理过什么突发事件？ |

### 3.5 教育 / 培训

| 维度 | 追问 |
|---|---|
| 规模 | 带几个班？多少学生？ |
| 成绩 | 及格率/优秀率/升学率变化？ |
| 课程 | 开发过几门课？有教材或课件吗？ |
| 教研 | 参与过什么课题？什么级别？ |
| 竞赛 | 辅导学生获过什么奖？几个人次？ |
| 管理 | 当过班主任吗？几年？流失率/家长满意度？ |
| 影响 | 做过公开课/讲座吗？给同行培训过吗？ |

### 3.6 医护

| 维度 | 追问 |
|---|---|
| 规模 | 什么科室？管几张床？日均接诊/护理多少人次？ |
| 操作 | 独立完成多少例什么操作？ |
| 急危重症 | 参与过多少次抢救/应急处置？ |
| 质控 | 参与过质控检查吗？写过流程/SOP 吗？ |
| 带教 | 带过几个实习生/进修生？ |
| 满意度 | 患者满意度？有没有收到过表扬/处理过投诉？ |

### 3.7 制造 / 工程 / 现场

| 维度 | 追问 |
|---|---|
| 范围 | 负责几条产线？几台设备？多大场地？ |
| 指标 | 良率/稼动率/停机时间改善前后？ |
| 安全 | 连续多久零事故？ |
| 改善 | 做过什么工艺改进？省了多少钱？ |
| 精益 | 参与过 5S/精益项目吗？节约额？ |
| 人员 | 带几个班？多少人？ |

### 3.8 设计（平面 / UI / 工业 / 建筑）

| 维度 | 追问 |
|---|---|
| 产出 | 年产多少稿？上线多少？ |
| 复用 | 做过设计系统/组件库/规范吗？多少人在用？ |
| 效果 | 改版前后转化/点击/停留的变化？ |
| 案例 | 有没有拿得出手的上线案例/获奖？ |
| 协作 | 跟产品/前端怎么配合？有没有推动过方案落地？ |

### 3.9 客服 / 运营 / 内容

| 维度 | 追问 |
|---|---|
| 量级 | 日均接待量/工单量/产出篇数？ |
| 指标 | 满意度、首解率、响应时长前后对比？ |
| 内容 | 阅读量/播放量/涨粉？爆款是哪条？ |
| 活动 | 策划过什么？参与量？转化率？ |
| 沉淀 | 写过话术/SOP 吗？团队在用吗？ |
| 危机 | 处理过什么舆情/大客诉？怎么收的场？ |

### 3.10 通用兜底：职能部门最容易漏的六个问题

**不管什么岗位，这六问都问一遍。** 它们的共同点是问"超出职责描述的部分"——
而那正是简历上真正有区分度的部分。

1. **你做的表/模板/流程/工具，现在还有人在用吗？几个人在用？**
   （从"会做"升级为"交付了别人在用的东西"）
2. **你教会过几个人？**
   （带教 = 隐性资历，几乎没人主动写）
3. **你替公司省过钱，或者避免过什么损失？**
   （风控 / 降本 / 纠错，金额是多少）
4. **有没有哪件事是没人要求你做、你自己去做的？**
   （主动性，且往往是成就感最强、记忆最清晰的事）
5. **你接手的时候是什么状况？你走/交接的时候是什么状况？**
   （前后对比，最容易挖出数字）
6. **别人做这件事，一般会卡在哪？**
   （难点。结果可以注水，难点编不出来）

## 4. 被遗忘的素材角落

用户以为自己"没什么可写"，通常是因为**只在回忆正式工作**。
以下材料源按价值排序，直接问用户要：

| 材料源 | 价值 | 为什么 |
|---|---|---|
| **述职 PPT / 绩效自评** | ★★★★★ | 天然含量化数字、贡献边界、项目名，且是用户自己写的、背得下来 |
| **周报 / 日报** | ★★★★ | 碎片但真实，能拼出完整项目线与时间线 |
| **工单系统 / JIRA / 禅道** | ★★★★ | 可查证的产出记录，含"谁做的、做了多少" |
| **内部培训 PPT / 分享稿** | ★★★★ | 证明"被人认可到可以教别人" |
| **新人入职文档 / 操作手册** | ★★★ | 你写的 = 你在团队里的技术权威位置 |
| **报销系统 / 出差记录** | ★★★ | 反推参与过的项目与客户 |
| **公司内网新闻稿 / 公众号** | ★★★ | 提到你名字的公开记录 = 第三方佐证 |
| **邮箱「已发送」** | ★★ | 你对外承诺过什么、推动过什么 |
| **微信群 / 聊天记录** | ★★ | 救火现场，常藏着"我解决了别人解决不了的问题" |
| **旧简历** | ★★ | 结构完整但常是低质量源头，只能当线索不能当素材 |
| **证书 / 培训结业证** | ★★ | 补证书段，且证明持续学习 |
| **兼职 / 接私活 / 帮朋友的忙** | ★★★ | **最常被漏掉**。用户觉得"不算正式工作"，但它常是唯一有从 0 到 1 的事 |
| **志愿 / 社团 / 业委会 / 自媒体** | ★★ | 校招与转行者的重要补充 |
| **网店 / 家庭作坊 / 个人项目** | ★★ | 同上，且自带数据 |

> **话术**："这些不用你整理，直接丢给我就行——哪怕是很久以前的、很零碎的都行。
> 我来挑能用的，挑完给你确认。"

**降低用户的整理成本，是配合度的第一杠杆。**
让他"丢过来"，而不是让他"填表"。

## 5. 篇幅反馈回路

挖掘不是一次性的，是**跟着篇幅诊断走**：

```
① 采集一轮素材
      ↓
② 跑 density → 得到「还差 N 行」
      ↓
③ 按本手册优先级追问：
     P1 漏采的经历/项目   → 第 4 节材料源 + 第 3 节职业族清单
     P2 已有 bullet 补结果 → 第 2 节线索追猎「缺失：结果」
     P3 已有 bullet 补难点 → 第 3 节「难点」维度
     P4 每段补足 2-3 条   → 第 2 节六问
      ↓
④ 回到 ②，直到 density 报「篇幅达标」
      ↓
⑤ 交给 polish 做改写（见 polish-playbook.md）
```

**每一轮都要让用户看到进展。** 采集完立刻渲染一版给他看，
"你的简历从半页变成一页了"——这个可见的变化，是让用户继续配合的唯一动力。

## 6. 提问预算与止盈

用户不配合是常态。**纠缠的代价大于收益。**

| 规则 | 值 |
|---|---|
| 同一条经历最多追问 | **3 轮** |
| 同一维度最多换问法 | **2 次** |
| 用户说"不记得/没有/差不多" | 立即标 `pending`，换下一条 |
| 用户明确不想答 | 跳过，写入 `gaps` |

**止盈线**：density 报"篇幅达标"就停。**不要为了凑篇幅继续挖。**
超出一页的简历比一页的更难读，而"篇幅焦虑"驱动的追问只会换来低质量素材。

## 7. 三条硬边界

1. **挖掘 = 问出用户已经有的东西，不是替他想出他没有的东西。**
   追问"有没有可能是 X？"是引导；直接写"你做了 X"是编造。
2. **用户说"好像是""大概""应该"时，标 `pending`，不要当成确认。**
   模糊回答不是授权。
3. **不要为了填满一页而把弱素材写进去。**
   density 报"还差 5 行"时，正确做法有时是**承认这份简历就这么多**——
   宁可交付一份短而实的，也不交付一份长而虚的。把选择权给用户。

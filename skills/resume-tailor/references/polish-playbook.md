# 润色手册

> 上游：`mining-playbook.md`（挖素材）→ 本手册（改写法）
> 下游：`scripts/polish.py`（机械体检）+ `scripts/density.py`（篇幅校验）

---

## 0. 润色到底在改什么

**润色不产生新事实，只改变读法。** 这是它与编造的唯一分界线，也是全部合法空间。

一条素材从采集到成稿要过三道关，每道关解决不同的问题：

| 关 | 问题 | 处理 |
|---|---|---|
| **① 有没有** | 这条素材是否真实存在 | 采集阶段解决，润色无能为力 |
| **② 说没说清** | action/object/method/result/difficulty 缺哪几项 | 本手册第 2 节补齐 |
| **③ 说得好不好** | 同一事实的表述层级与读感 | 本手册第 3–5 节改写 |

**大多数人以为润色是第 ③ 关，其实 80% 的收益在第 ② 关。**
一条"负责数据处理工作"改十遍还是"负责数据处理工作"；
但只要问出"多久搞一次、量多大、之前怎么做、现在谁在用"，它自己就变强了。

## 1. Bullet 四级模型：先给每条定位

**改写之前必须先知道这条在第几级。** 不同级别的 bullet 改法完全不同——
对 L0 讲"换个动词"没用，它缺的是内容不是措辞。

| 级 | 定义 | 样例 | 判据 | 处理 |
|---|---|---|---|---|
| **L0 职责型** | 只说了"我负责什么"，没说做了什么 | 负责应收账款管理 | 无 method、无 result | **回采集，不要润色** |
| **L1 行动型** | 说了做了什么、怎么做 | 用透视表模板重构账龄分析 | 有 method，无 result | 补 result → L2 |
| **L2 结果型** | 有可验证的变化 | 月结对账耗时从 3 天降至 1 天 | 有 result，**无 difficulty** | 补 difficulty、影响范围 → L3 |
| **L3 影响型** | 结果 + 影响面 + 难点，且能抗三层追问 | 搭建账龄分析模板（Excel 透视表），月结对账耗时 3 天→1 天，覆盖全厂 20 余家客户，现由财务同事每月自助刷新 | 五要素齐全 | 只调措辞与顺序 |

**目标分布**：一段经历里 L2 以上占 60%+，至少 1 条 L3。
**全是 L0 的经历段 = 这段没有采集成功**，回到 mining-playbook 重挖。

## 2. 补五要素（第 ② 关，收益最高）

每条 bullet 检查五要素，缺哪个补哪个。**补的顺序即重要性顺序。**

### 2.1 result（结果）—— 最常缺，也最致命

没有结果的 bullet 在 HR 眼里等于"做了，但不知道做得怎么样"。

**七维度试探**（见 mining-playbook 3.x 各职业族）：规模 / 效率 / 质量 / 钱 / 人 / 对比 / 范围

**拿不到精确数字时的三条退路**（按优先级）：

1. **范围值**："约 30–40 家" "接近一半"
2. **相对变化**："从每周 2 次减到每月 1 次"（频次也是数字）
3. **定性但可验证**："交付后由业务同事自助使用，不再需要我介入"
   —— 这是**影响**，不是注水，面试官一问"谁在用"就能验证

**绝对不能做**：编一个"提升 40%"。这条红线是全部信任的基础。

### 2.2 difficulty（难点）—— 最易被跳过，却最抗追问

**结果可以注水，难点编不出来。** 面试官追问三层时，编的第三层必崩。

三种问法（用户答不上第一种就换下一种）：
1. "这件事里最让你头疼的是哪一步？"
2. "如果换个人来做，他可能卡在哪？"
3. "有没有哪次差点没做成？后来怎么解决的？"

### 2.3 boundary（边界）—— 不写在成稿里，但必须问清楚

**边界不出现在简历正文**，它决定动词能不能用"主导"。
团队 4 人里做了一块，动词只能是"负责……部分"或"参与"。

### 2.4 method（方法）—— 关键词的藏身之处

method 是 ATS 关键词的天然位置：**工具名放这里，而不是单列在技能段**。

> ❌ 技能段写"熟悉 Excel"，bullet 写"优化了账龄分析"
> ✅ 技能段不写 Excel，bullet 写"搭建账龄分析模板（Excel 透视表 + 函数）"

关键词一个字没少，但主句从"会用一个软件"变成了"做出了一个东西"。

### 2.5 scope（影响范围）—— 一句话的事，但有和没有差一档

"覆盖全厂 20 余家客户" 比 "提升了效率" 强在**可验证**。

## 3. 改写五步法（第 ③ 关）

拿到一条 L1/L2 素材后，按序走：

```
① 定动词   —— 动作强度是否匹配真实贡献（见 3.1）
② 提对象   —— 把「做了什么」换成「交付了什么」
③ 藏工具   —— 方法里的工具名降级为括号注脚
④ 前置结果 —— 结果从句尾提到句中，让第一眼就看到变化
⑤ 加影响   —— 补上「谁在用 / 覆盖多广 / 后来怎样」
```

### 3.1 动词强度分级

**动词不是越猛越好，是越准越好。** 用超过证据强度的动词，等于邀请对方追问到崩。

| 强度 | 动词 | 适用 |
|---|---|---|
| **弱**（参与层） | 参与、协助、配合、跟进 | 团队中做了一部分，说不清自己的贡献占比 |
| **中**（执行层） | 负责、完成、开发、编写、处理、维护 | 独立完成一块，但方案不是你定的 |
| **较强**（方案层） | 设计、搭建、重构、优化、推动、建立 | 从 0 到 1，或方案是你选的 |
| **强**（决策层） | 主导、统筹、从 0 搭建、牵头、负责整体 | 有决策权，且**必须挂 evidence** |

**强动词的硬规则**：写"主导"必须能回答"团队几个人、你决策了什么、谁向你汇报"。

### 3.2 对照表：平淡 → 有力

| 类型 | 改写前 | 改写后 | 改了什么 |
|---|---|---|---|
| 职责 → 交付 | 负责公司数据处理工作 | 搭建部门数据分析流程，月报出数从人工 2 天压缩至 1 小时 | 补结果、提对象 |
| 工具 → 产出 | 熟练使用 Excel 和 SQL | 搭建应收账龄分析模板（Excel 透视表），全厂 20 余家客户月度对账耗时 3 天→1 天 | 藏工具、补范围 |
| 参与 → 贡献 | 参与 XX 项目开发 | 负责 XX 项目的推荐召回模块（团队 4 人），优化后点击率提升 X% | 补边界、补结果 |
| 过程 → 结果 | 对算法进行了多次调优 | 经 5 轮参数与特征迭代，识别准确率从 X% 提升至 Y% | 补量化 |
| 单个 → 体系 | 写了几个自动化脚本 | 沉淀 6 个数据处理脚本并整理为部门操作手册，新同事按文档即可上手 | 加影响 |
| 做完 → 在用 | 完成了报表自动化 | 交付报表自动化工具后移交业务同事自助使用，不再需要技术介入 | 加影响 |
| 无难点 → 有难点 | 搭建了内网平台 | 在内网隔离环境（无外网、无云服务、无第三方组件源）下从零搭建前后端分离的数据分析平台 | 加难点 |
| 笼统 → 具体 | 提升了系统性能 | 通过引入缓存与查询重写，列表页 P95 响应时间从 2.3s 降至 380ms | 补量化、补方法 |

### 3.3 顺序调整

同一条 bullet 内，**信息的重要度决定位置**：

> 结果前置：`X 从 A 降到 B —— 通过 M 方法作用于 O 对象`
> 常规语序：`针对 O 对象，采用 M 方法，实现 X 从 A 降至 B`

**中文简历推荐常规语序（方法→对象→结果）**，因为：
- 结果前置读起来像营销文案，技术岗与职能岗都偏反感
- 但**结果必须出现在句子后半段的第一眼位置**，不能埋在从句里

## 4. 三候选交互格式

**改写不是替用户决定，是给用户选择。** 每次改写给 3 个候选，附理由与风险。

```
【原文】
  负责公司数据处理工作

【候选 A｜保守】保留了你的原话，只补结构
  负责公司数据处理工作，搭建月报自动化流程，出数耗时从 2 天缩短至 1 小时
  理由：改动最小，面试时你怎么说都不会穿帮
  风险：动词「负责」偏弱，看不出独立程度

【候选 B｜推荐】把「做了什么」改成「交付了什么」
  搭建部门月报自动化流程（Python + MySQL），出数耗时从 2 天缩短至 1 小时，
  现由业务同事自助刷新
  理由：动词升到「搭建」有交付物支撑；工具降级为注脚；补了影响面
  风险：需确认「业务同事自助刷新」是否属实

【候选 C｜激进】强调从 0 到 1
  从零搭建部门月报自动化流程，替代原有人工统计，出数耗时 2 天→1 小时
  理由：突出从 0 到 1
  风险：「从零」需确认原流程确为纯人工，若原本有半成品则不可用
```

**三条规则：**

1. **候选之间必须真的不同** —— 三个版本只有形容词差别，等于没给选择
2. **每个候选都要写「风险」** —— 不写风险的推荐是推销
3. **默认推荐中间档** —— 最激进的那个通常也是面试时最容易崩的那个

## 5. 段落级润色

### 5.1 摘要（社招最强去 low 手段）

三行结构：**身份 → 核心能力 → 差异化**

```
【身份】X 年 Y 方向经验，前 N 年做 A，近 M 年做 B
【能力】具备 C 能力（用交付物证明，不用形容词）
【差异】在 D 这类受限/特殊条件下仍能独立闭环
```

**要点**：
- 不写"性格开朗、抗压能力强"（不可验证）
- 时间拆分要**真实对齐经历**，不能为了好看把短期经历说长
- 每行一个信息点，不堆砌

### 5.2 技能段

- 分类按**能力域**，不按技术类型（见 SKILL.md「low 感」清单）
- 主句是能力，工具名是注脚：`BERT 微调（PyTorch / Transformers）`
- 不写熟练度（"熟悉""精通"）
- 单组不足 2 项则合并或改写为能力陈述

### 5.3 经历段

- 每段 2–3 条 bullet，超过 4 条说明该拆段或该合并
- 按与 JD 的相关度排序，不是按时间排序
- **最近一段经历的 bullet 数应该最多**（除非某段早期经历与 JD 高度吻合）

## 6. 体检清单（交给 polish.py 的部分）

以下可机械判定，已落进 `scripts/polish.py`：

| 检查 | 判定 | 处理 |
|---|---|---|
| 缺 result | result 为空 | 补量化或补影响 |
| 缺 difficulty | difficulty 为空 | 补难点 |
| L0 职责型 | 无 method 且无 result | 回采集 |
| 强动词无证据 | action 属强动词组且 evidence ≠ verified/self_reported | 降级动词 |
| 句首重复 | 同段多条 bullet 动词相同 | 换动词 |
| 过长 | bullet 超过 3 行 | 拆分或砍修饰 |
| 过短 | bullet 不足 1 行 | 补要素 |
| 占位残留 | 含"待补""待确认""无" | 清账 |

以下**只能人工判断**，脚本不碰：措辞是否自然、层级是否匹配贡献、读感是否"low"。

## 7. 润色的三条硬边界

1. **润色不能补事实。** 发现缺 result 的正确动作是**去问用户**，不是在句尾加一个数字。
2. **润色不能升级 evidence。** `pending` 的内容改十遍还是 `pending`，出片照样隐藏。
3. **润色不能覆盖 `raw_input`。** 原话是防漂移的锚，改写结果放 `rewrite_candidates`。

> **一句话检验**：把改完的句子念给用户听，问他"这是你做的事吗？"
> 他犹豫了，就是改过头了。

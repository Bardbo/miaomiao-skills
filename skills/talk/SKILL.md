# Talk — 多角色对话模拟

模拟 2 名或多名角色之间的沉浸式对话或讨论。**agent 按本文档步骤执行，不依赖 Python 状态机。**

## 核心原则

1. **SKILL.md 就是状态机** — agent 读文档按步骤走，不靠 Python 代码推进流程
2. **Python 脚本只做 agent 做不了的事** — 搜索本地技能、检测仓库、验证输出
3. **逐句生成** — 禁止一次性生成整段对话，每句调用一次
4. **违规事前约束 + 事后检查** — 生成时参照规则自我约束，生成后用脚本验证

## 执行流程（4 步）

### Step 0: 检查必填项

| 信息项 | 必需 | 说明 |
|--------|------|------|
| 角色 | ✅ | 角色列表，用逗号分隔（如 "巴菲特,芒格,马斯克"） |
| 场合 | ✅ | 对话发生的场景/场合（如 "巴菲特股东大会后的鸡尾酒会"） |
| 主题 | ✅ | 讨论的核心议题（如 "AI 对价值投资的影响"） |
| 长度 | ✅ | 大概轮次数（每轮 = 所有角色各说一次，共 N 句；3人对话每轮3句） |

**🔴 禁止自行补充：** 以上任何一项未提供，必须列出缺失项并询问用户，**不得使用默认值**。

**🔴 输出格式强制：** 最终对话文本必须以场景说明开场（格式：`# {场合}：{角色清单}`），不得直接开始对话。场景说明不计入角色轮次。

**🔴 CHECKPOINT · Step 0 必填项已确认 → 进入人格检测**

### Step 1: 人格检测

对**每个角色**，按优先级链检测。**每发现一个技能都要询问用户是否使用。**

检测命令：
```bash
python3 scripts/persona_detector.py detect --char "角色名"
```

| 优先级 | 方法 | 说明 |
|--------|------|------|
| 1 | 本地已安装 skills | 自动检测 → 发现后询问用户 |
| 2 | 仓库搜索 | 自动搜索 awesome-ai-persona-skills + 名人独立仓库 → 发现后询问用户 |
| 3 | nuwa 蒸馏 | **不自动执行，询问用户**是否用 huashu-nuwa 蒸馏 |
| 4 | Fallback 构建 | 基于公开信息由 agent 构建人格描述 |

**用户确认流程：**
1. 脚本输出检测结果 → 展示给用户 → 询问是否使用
2. 用户确认 → 用 skill_view(name) 加载该人格 skill
3. 用户拒绝 → 继续下一级检测
4. **ALL levels exhausted — 脚本返回「无结果」→ 不要直接进入 Fallback**
   - ⚠️ 这是最容易跳步的地方。脚本返回空不代表用户没选择。
   - 必须将检测结果（Level 1 无、Level 2 无、Level 3 nuwa 可用）展示给用户
   - 用 clarify 问：**"没有现成的人格 skill。要用 nuwa 蒸馏一个，还是我搜资料手写 Fallback？"**
   - 用户选择 nuwa → 加载 huashu-nuwa 技能蒸馏
   - 用户选择手写 → 按 Fallback 格式构建，构建完成后再展示给用户确认
5. **Fallback 确认环节：** Fallback 构建完成后，必须用 clarify 展示给用户：「这是我为 X 构建的硬约束表，确认用这个吗？」 用户确认后才能进入 Step 2。

**🛑 STOP · 人格已确认 → 进入逐句生成。所有角色必须加载了人格 skill 或 Fallback 后才能继续。**

**Fallback 人格构建格式（agent 自行完成，不依赖脚本）：**
```json
{
  "name": "角色名",
  "thinking_style": "理性/感性/比喻/实用…",
  "emotional_rhythm": "急躁/沉稳/幽默…",
  "core_stance": "核心立场（一句话）",
  "catchphrase": "标志性用语",
  "source": "Fallback 构建",
  "disclaimer": "以下内容为基于公开信息的推断，不代表角色实际说过或做过。"
}
```

### Step 2: 生成对话

> **⚠️ 用户选择环节：** 在生成开始前，**必须询问用户**选择哪种生成方式。
>
> | 方式 | 说明 | 适用场景 |
> |------|------|---------|
> | **一次性生成（默认）** | agent 一次生成完整对话文本（单次 API 调用），生成后用 validator 检查 | 快速出稿、短对话（≤6轮）、用户不要求逐句精度 |
> | **逐句生成（高精度）** | 每句单独调用一次 LLM API，每次都携带完整历史上下文，逐句追加到文件 | 长对话（≥8轮）、用户明确要求"逐句生成"、精细化角色一致性要求高 |
>
> **流程分叉：**

### 2a. 一次性生成（默认）

agent 内部一次性生成完整对话。提供最终完整文本，然后进入 Step 3 验证。

**约束条件与 Step 2b 相同**——所有对话自然度规则（禁止目录式推进、三明治法则、幽默指南）、违规规则（第三人称指代、旁白、超长发言）在此模式下同样强制执行。

### 2b. 逐句生成（高精度）

**agent 通过 Python 脚本逐句调用 LLM API，不走 agent 手动轮次循环。** 每次调用携带完整历史上下文，每次只生成一个角色的一句话。

**执行方式：**
- 对于 ≤6 轮的小对话：agent 可在上下文中手动逐句生成（每句一次 tool call）
- 对于 ≥8 轮或长对话：**必须用 `execute_code` 或 `terminal` 执行 Python 脚本**，脚本通过 `openai` 库（或 requests 调用兼容的 API 端点）逐句调用当前模型

**Python 逐句生成脚本模板（用于 `execute_code`，含 Blueprint + RPM 保护）：**

```python
import json, requests, yaml, re, time

# ===== 配置（自动从 Hermes config 读取）=====
config = yaml.safe_load(open('C:/Users/Administrator/AppData/Local/hermes/config.yaml'))
API_KEY=config['model']['api_key']
BASE_URL = config['model']['base_url'].rstrip('/')
MODEL = "deepseek-v4-flash"  # 替换为当前模型

CHARACTERS = ["角色A", "角色B"]  # 按发言顺序
ROUNDS = 12
OUTPUT = "./dialogue.md"

# ===== BLUEPRINT（全局主题锚点，防止逐句漂移）=====
BLUEPRINT = """对话主题：...
自然覆盖以下话题（不是按顺序念，是通过对话自然涉及）：
1. ...
2. ...
3. ...

对话规律：话题从角色互动中自然生长，不按清单念。"""

# ===== 人格定义（从 skill_view 提取关键特质，注意平衡）=====
PERSONAS = {
    "角色A": "...（避免过于放大某一负面特质）",
    "角色B": "...",
}

# ===== 系统指令模板（含 Blueprint）=====
SYSTEM_TEMPLATE = """你正在扮演 {speaker}。用第一人称「我」说话，直接对 {listener} 发言。
称呼对方必须用「你」（第二人称），绝不能以「他」「她」或对方全名来指代当面的人。

【角色人格】
{persona}

【对话整体主题参考】（不是提纲，是背景）
{blueprint}

【对话历史】
{history}

【当前轮次】
第 {round_num} / {total_rounds} 轮

请以 {speaker} 的身份说出下一句话（仅输出台词本身）："""

# ===== 逐句生成 =====
print("Testing API...")
resp = requests.post(f"{BASE_URL}/chat/completions",
    headers={"Authorization": f"Bearer {API_KEY}", "Content-Type": "application/json"},
    json={"model": MODEL, "messages": [{"role": "user", "content": "ping"}], "max_tokens": 5}, timeout=15)
assert 'choices' in resp.json(), f"API failed: {resp.json()}"

history = []
with open(OUTPUT, "w", encoding="utf-8") as f:
    f.write("# 对话标题\n\n")

for r in range(1, ROUNDS + 1):
    for speaker in CHARACTERS:
        listener = CHARACTERS[1] if speaker == CHARACTERS[0] else CHARACTERS[0]
        hist_text = "\n".join(history[-6:]) if history else "（对话刚开始）"

        prompt = SYSTEM_TEMPLATE.format(
            speaker=speaker, listener=listener,
            persona=PERSONAS[speaker], blueprint=BLUEPRINT,
            history=hist_text, round_num=r, total_rounds=ROUNDS
        )

        # Retry loop for RPM limits
        for attempt in range(2):
            try:
                resp = requests.post(f"{BASE_URL}/chat/completions",
                    headers={"Authorization": f"Bearer {API_KEY}", "Content-Type": "application/json"},
                    json={"model": MODEL, "messages": [{"role": "user", "content": prompt}],
                          "max_tokens": 300, "temperature": 0.8}, timeout=45)
                data = resp.json()
                if 'choices' not in data:
                    if 'rpm' in str(data).lower():
                        print(f"  [RPM, retry 5s...]")
                        time.sleep(5)
                        continue
                    print(f"ERR r{r} {speaker}: empty response")
                    break

                raw = data['choices'][0]['message']['content'].strip()
                if not raw:
                    print(f"ERR r{r} {speaker}: empty content")
                    break

                raw = re.sub(r'^[**]?(角色A|角色B)[：:]\s*', '', raw)
                formatted = f"**{speaker}：** {raw}\n\n"
                with open(OUTPUT, "a", encoding="utf-8") as f:
                    f.write(formatted)
                history.append(f"{speaker}：{raw}")
                print(f"[{r}/{ROUNDS}] {speaker}: {raw[:60]}...")
                time.sleep(0.5)  # RPM cushion
                break
            except Exception as e:
                print(f"ERR r{r} {speaker}: {e}")
                time.sleep(3)
                break
```

**🎯 对话自然度规则（必须遵守）：**

**1. 不要抄目录式推进主题。** 用户可能给了多个话题点（如「中介思维→产品思维→平台」），但角色之间的对话不是上课。**不允许**逐条按顺序念完用户的提纲。

覆盖策略：
- **当用户提供话题清单时：必须覆盖清单中所有核心话题**，不能只选2-3个遗漏其他
- 但覆盖方式必须是**自然的对话流**：每个话题通过故事、反驳或延伸自然引出，而非逐条念清单
- 正确做法：生成前将话题映射为**对话场景**（每个场景含2-3句对话自然展开一个话题），让话题之间的过渡通过角色互动自然完成
- 错误做法：先问「那咱们聊聊下一个话题——XXX」或「说完XX，我们来谈谈YY」，这种过渡像幻灯片翻页

**2. 话题转换用「三明治法则」：**
- 前一层：用一句总结/评价收束前一个话题（如「你说的这个让我想起另一件事」或「说到底，这些都是同一类问题」）
- 中间层：用自然的桥梁过渡—— disagreement（「我不完全同意」）、延伸（「更进一步说」）、故事（「这让我想起1988年的一件事」）、反问（「你知道最有意思的是什么吗？」）
- 后一层：抛出新的具体观点或故事，自然开启新话题
- 禁止：突然说「那咱们聊聊下一个话题」或直接跳到下一个点

**3. 幽默与人格深度：**
- 生成前回顾角色人格 skill 中的「表达DNA」章节，确保语气、幽默方式、句式偏好和角色一致
- 幽默要「从角色嘴里长出来」——巴菲特的幽默是自嘲+干燥+棒球类比，芒格是毒舌+荒诞类比，不是通用的讲笑话
- 每3-4轮至少出现一次角色特有的幽默或生动的类比
- 如果角色人格 skill 中有「与XX对比」的条目（如buffett-perspective中有「与芒格的区别」表），主动利用这些差异制造对角互动

**4. 句式变化规则：** 同一对话中，每个角色的开场句式必须有足够的变化。禁止在同一篇对话中出现超过2次相同的开场句式结构（如「你说得对，XXX」「你发现没有」「说到这个，让我想起」「我讲个例子」「你猜怎么着」）。生成每句话前，回顾历史记录检查之前用过的开头方式，选择不同的句式。

**5. 具体例子要求：** 每个讨论的思维模式、投资原则或核心观点，必须配一个**具体的商业案例或历史故事**说明（如弹子球机比喻中介思维、See's巧克力说明定价权、美国运通讲平台效应），而非纯理论叙述。不同的观点要用不同的故事，不要复用同一个例子。

### 🎭 规则6: 活人感规则 — 让对话像真实交谈

这组规则的目标是解决对话最常见的毛病——读起来像两段结构工整的演讲稿交替上场，而不是两个活人在聊天。

**核心原则：真实对话的第一特征是「不完美」——打断、重复、语气词、抢话、接话、情绪起伏，才是活人感。**

#### 6.1 打断与接话（打断是活人感的最高杠杆）

- 角色**不必等对方说完才开口**。在对方说到关键词时，可以自然地接过话头：「等等」「就是这个点」「哈！你终于说到这个了」「诶，你提起这个我想起一事」
- 当两个角色的观点高度一致时，**加速节奏**——一人说半句，另一个接下半句（「所以你的意思是——」「对，就是这个意思」）
- 当两个角色的观点有张力时，**放慢节奏**——需要停顿、反问、重新解释（「我不太同意这点…」「你等等，你刚才说的和这个矛盾了」）
- **打断的三种合法形态：**
  - 抢话接尾：A说到一半，B把后半句补完
  - 追问打断：A说一个点，B立刻追问「等等，你说的XX具体指什么？」
  - 反驳打断：A说一个观点，B直接截停「我不这么看。你听我说完」
- **禁止：** 每次都是A说完→B说「你说得对/说到这个，让我想起」→A说完→B重复同一模式。连续出现2次此结构就改变。

#### 6.2 语气词与情绪标记（去掉书面感）

- 每个角色至少每隔3轮使用一次口语语气词：「嗯…」「哈！」「诶，」「对了」「好家伙」「你瞧瞧」「你听我说」
- 情绪不能只有平和交流——必须出现以下情绪层次中的至少3种：
  - **疑惑**：嗯？等等、你确定？
  - **恍然/认同**：对！就是这个理、你说到点子上了、哈！我明白了
  - **反对/质疑**：我不觉得、你等等、这说不通、你刚才说的前后矛盾了
  - **感慨**：唉、说来说去啊、这让我想起…
  - **幽默**：干燥自嘲（巴菲特擅长）、毒舌比喻（芒格擅长）——幽默必须是角色嘴里长出来的，不是硬插的笑话
- **情绪词必须融合在对话流中**，不能写成「巴菲特感慨道：唉…」——直接用「唉，说来说去啊」

#### 6.3 人格表达DNA强制执行 — 角色专属硬约束（最高优先级 ◆ 违反即重写）

这是活人感规则的**最高优先级**。生成前**必须用 skill_view() 加载每个角色的人格skill的"表达DNA"章节**。然后对每个角色应用其专属硬约束表。

##### 硬约束表格式

>`句数上限` / `禁止句式` / `必须出现` / `开头规则` / `类比偏好` / `情绪基调`

每个角色生成前，把硬约束表逐条对照。

##### 巴菲特

| 维度 | 硬约束 | 反例 | 正确 |
|------|--------|------|------|
| **句数上限** | 每轮 **≤ 3句**（含承接语，如「对！」算一句） | 5句讲浮存金的故事 | 砍到3句：「对！两层钱算什么。保险——浮存金，客户先交保费，我拿去投资。不用还利息的杠杆。」|
| **禁止句式 ①** | ❌ 禁止「这叫XX/这就是XX/后来我知道这叫XX」的教育式总结句 | 「这叫中介思维：你降低交易成本…」 | 直接说事实，让听众自己总结：「机器放店里，对半分，两边都需要我」|
| **禁止句式 ②** | ❌ 禁止用定义式语句解释概念 | 「定价权是最好的护城河」 | 用画面说：「提价3%，没人跑」|
| **禁止句式 ③** | ❌ 禁止「说到XX让我想起」的过场句式 | 「说到升级，我想起Mrs.See的巧克力店」 | 直接切：「你怎么做到的？——Mrs.See一辈子没想过做便宜货」|
| **必须出现** | 每3轮至少一次 **自嘲漫画** | 全程正经讲投资 | 「我坐了36年，除了喝汽水什么都没干」「我什么也没做，就是坐着」|
| **必须出现** | 每轮 **先具体再抽象**（先故事后道理，或不讲道理只讲事） | 先讲抽象概念 | 先讲弹子球机故事，不说中介思维这个词 |
| **开头规则** | 短句 **直接接话**——重复或推进对方的关键词 | 长篇回应 | 「对！就是那台」「升级嘛…」「嗯，你说的这个我想起一事」|
| **类比偏好** | **棒球 > 农场/荒岛 > 日常 > 商业**。至少用1次棒球类比 | 只用商业案例 | 泰德·威廉姆斯击球区理论 |
| **情绪基调** | 温和、轻松、像在 **Dairy Queen聊天** | 说教式语气 | 用生活画面翻译抽象概念 |

##### 芒格

| 维度 | 硬约束 | 反例 | 正确 |
|------|--------|------|------|
| **句数上限** | 每轮 **≤ 2句**（⚠️ 句数上限是芒格表达DNA**最关键的一条**） | 5句讲杠杆+爆仓+浮存金 | 砍到2句：「漂亮。但大多数人学歪了——以为杠杆就是借钱。爆仓都是借了还不起的。」|
| **禁止句式 ①** | ❌ 禁止「不铺垫」 — 芒格从不做铺垫式开场 | 「嗯…产品做到极致了，然后呢？」 | 直接：「然后呢？美国运通。」|
| **禁止句式 ②** | ❌ 禁止委婉语、软化措辞 | 「可能不太对」「也许是这样」「这个方案有些不足」 | 用 blunt 词：「这很蠢」「那是疯了」「行不通」|
| **禁止句式 ③** | ❌ 禁止连续3句以上不打断对方（芒格是**打断方**，不是乖乖等对方说完的人） | 等巴菲特说完才回应 | 在巴菲特说到关键词时截停：「等等」「不对」「你这话有问题」|
| **必须出现** | 每5轮至少一次 **blunt level 否定词**（蠢/疯了/行不通/骗人/白费功夫） | 全程客气评价 | 「你那个浮存金漂亮。但借钱玩杠杆？那是疯了。」|
| **必须出现** | 每5轮至少一次 **否定句优先** 的句式 | 「大多数人需要耐心」 | 「大多数人不是能力不够——是扛不住第三声不行。」|
| **开头规则** | 结论在前，解释在后。**第一句就给出判断** | 「坚持不要脸是有道理的，因为…」 | 「我那个叫坚持不要脸。不是耍无赖，是换条路。」|
| **类比偏好** | 粗俗但精准的 **向下类比**（粪便/老鼠药/看牙医/性病 > 商业 > 经典引用） | 只用常规商业比喻 | 「葡萄干拌屎还是屎」级别的粗俗精准 |
| **情绪基调** | 干燥、严肃、不用感叹——**表情越少越好笑** | 「哈！你倒是自己发现了」（太热情） | 用平调：「信息差会消失。穿帮是早晚的事。」|
| **沉默规则** | 用沉默表态。**「我没什么要补充的」比任何解释都更有力** | 什么都解释 | 收尾直接用：「我没什么要补充的了。」|

##### 执行方式（逐句验证，违反≥1条即重写）

```
for each 角色发言:
  1. 数句子数 → 超上限? 砍句直到 ≤ 上限
  2. 检查禁止句式 → 有禁止句式? 重写
  3. 检查必须出现 → 累计轮次到触发条件还没出现? 加
  4. 检查开头规则 → 不符合? 重写第一句
  5. 检查类比偏好 → 基本符合?
  6. 检查情绪基调 → 太 soft/太热情? 调整

if 任意一项不通过:
  → 重写整句
```

#### 6.4 对话节奏曲线（避免通篇匀速）

整篇对话不能全是同一节奏。理想曲线示例：

| 阶段 | 节奏 | 说明 |
|------|------|------|
| 开场（第1-2轮） | 短-短-快 | 用短句快节奏开场，像真实对话里的寒暄或直入主题 |
| 中段（第3-6轮） | 中-中-短-长 | 讨论展开，有来有回——短的追问+中的解释+偶尔长的叙述 |
| 高潮（第7-8轮） | 中-长-短 | 核心观点用稍长叙述展开，然后立刻用短句收束 |
| 收尾（第9-10轮） | 短-短 | 总结性短句收尾，不拖沓 |

**节奏检查方法：** 生成完所有轮次后，逐轮标注句子长度（短:1-15字/中:16-40字/长:41+字），检查是否有连续3轮节奏完全一致。如果有，中间插入一句更短或更长的句子。

#### 6.5 呼应与追问（避免独角戏）

- 角色A说完后，角色B**不能只发表自己的新观点**而不回A。必须先用至少半句话回应A的上一个核心论点（哪怕是否定：「我不觉得这说明问题」「你说的那点其实有漏洞」）
- 每3轮至少出现一次直接追问：
  - 「你说的XX具体是什么意思？」
  - 「举个例子看看」
  - 「所以你是在说…？」（帮对方补完逻辑）
  - 「等等，这和我刚才说的矛盾吗？」
- 角色之间必须用「你」称呼对方。**禁止**在用「他」或全名指代正在当面说话的人。这条已经是违规项，但在此强调。

#### 6.6 对话连贯性 — 话题过渡不能断崖

这组规则解决的是对话的**结构性跳跃**——A说完一个话题，B不是接着推进同一个话题，而是跳到另一个不相关的概念。

**核心原则：从话题N到话题N+1，中间必须有且只有一条「角色说出来的连接」。如果删掉一句角色台词，两个话题之间就没有任何关系了，那就是断崖跳跃。**

##### 断崖判断法

```
for each 相邻对话轮 (R_N → R_{N+1}):
  1. 读 R_N 的结尾句(最后一人的发言)
  2. 读 R_{N+1} 的开头句(第一人的发言)
  3. 问：这两句话之间有因果关系/承接关系/反驳关系/延伸关系吗？
  
  如果「有」→ 通过
  如果「没有」→ 断崖跳跃，需要加桥
```

**实例：**

| 类型 | 例子 | 是否断崖 |
|------|------|---------|
| ✅ 有桥 | R3芒格「美国运通。顾客付一次，商家再付一次。」→ R4巴菲特「对！保险更漂亮——浮存金…」| 有桥：「对！」接住芒格的话，"保险更漂亮"是延伸 |
| ❌ 断崖 | R4芒格「但借钱玩杠杆？那是疯了。」→ R5巴菲特「泰德·威廉姆斯把击球区划成77个格子…」| 断崖！芒格刚说完杠杆风险，巴菲特跳到棒球，中间没有连接句 |
| ❌ 断崖 | R6芒格「能力圈。知道自己不知道什么，比知道什么重要。」→ R7巴菲特「哈！年轻时想合作，门都不让我进…」| 断崖！能力圈话题和合作故事之间没有关系 |

##### 三种合法桥接方式

**① 接话桥（首选）** — 角色B先直接用半句话回应A的上个结论，然后自然延伸/引出下一个点

> 芒格：借钱玩杠杆？那是疯了。
> 巴菲特：**确实。所以**我学泰德·威廉姆斯——77个格子，只打正中间的。
> → 「确实」接住芒格的话，"所以"引出下一个相关点

**② 追问桥** — 从A的上个观点中提取一个侧面追问，追问本身就是桥

> 芒格：能力圈。知道自己不知道什么，比知道什么重要。
> 巴菲特：**知道什么该等，还得敢等。** 年轻时想合作，门都不让我进…
> → 「知道什么该等」是对能力圈概念的延伸追问/延伸

**③ 故事桥** — 用A的上个观点触发一个个人回忆，故事本身是新话题的载体

> 芒格：信息差会消失。穿帮是早晚的事。
> 巴菲特：所以得升级。我不懂什么商业模式，但看得懂好生意——Mrs.See…
> → 「所以得升级」来自芒格的"穿帮"，故事是升级的证明

**禁止的桥接方式：**
- ❌ 目录式桥：「说到XX，让我想起XX」「那咱们聊聊下一个话题」
- ❌ 无头桥：角色B直接说一个和A完全无关的新事实，没有任何过渡

##### 角色专属桥接风格

| 角色 | 桥接风格 | 例句 |
|------|---------|------|
| 巴菲特 | **先接再引** — 先用「确实/对/说得对」接住对方，再用故事引出下一层 | 「确实。所以我学泰德·威廉姆斯…」「对。保险更漂亮——浮存金…」|
| 芒格 | **封顶开路** — 一句话把A的观点终结/定性，直接引出新角度 | 「信息差会消失。穿帮是早晚的事。」（封顶）→ 引出卖了就升级的逻辑 |

##### 话题簇概念

每篇对话的话题应组成 **2-3 个话题簇**（每组2-3轮），**簇内紧密，簇间有桥**：

```
[簇1: 中介→产品→平台] 3轮 → [桥] → [簇2: 杠杆→耐心→能力圈] 3轮 → [桥] → [簇3: 坚持→选人→靠谱] 3轮 → [收尾] 1轮
```

而不是10个概念各1轮像跳菜单。

**检查方法：** 生成完对话后，画一个话题地图：
```
R1: 弹子球机 → R2: 信息差会消失 → R3: 升级到产品 → R4: 平台/杠杆 → R5: 耐心/击球区 → R6: 能力圈 → R7: 坚持 → R8: 选人 → R9: 靠谱 → R10: 收尾
```
如果在话题地图上相邻的两个话题之间没有「A说了一个结论→B延伸/质疑/接了它」的句子，标记为断崖，需要加桥。

#### 6.7 神似规则 — 对话要像人，不像是素材展

这组规则解决对话最隐蔽的问题：**每句话单独看都对，连起来不像真人聊天**。角色在背自己的「代表作」，而不是在跟对方说话。

**核心原则：角色说的第一句话，必须是对对方上一句话的即时反应。任何标志性素材（巴菲特：泰德·威廉姆斯/Mrs.See/弹子球机；乔布斯：iPhone/iPod/被开除；爱因斯坦：相对论/指南针/专利局；芒格：葡萄干拌屎/能力圈等等）必须先证明它是被对话「触发」的，而不是被作者「投放」的。**

##### 6.7.1 即时反应优先 — 先有感才有思

真人聊天中，第一反应永远是情感的，不是智识的。听到一句话后先有：认同/疑惑/反对/好笑/吃惊/不屑，然后才组织语言。

**❌ 错误（直接跳到结论）：**
> 爱因斯坦：十年、一百年，从宇宙角度看是一样的。
> 乔布斯：你说得对，大多数创新是垃圾。但1%里的那一两个，可以改变世界。

→ 乔布斯跳过了对「宇宙角度」这个说法的第一时间感受，直接输出自己的完整观点。句子完美，但没有灵魂。

**✅ 正确（先有感，后出招）：**
> 爱因斯坦：十年、一百年，从宇宙角度看是一样的。
> 乔布斯：哈！宇宙角度。（摇头笑）我可等不了那么久。我等了十年才等到触控屏技术成熟。

→ 乔布斯先对「宇宙角度」有了即时情绪反应（笑+摇头），再引出自己的真实态度。

**检查方法：** 读角色发言的前三个字——如果是情感反应词（哈/嗯/对/不/这/等等/有意思/荒谬/有趣/好笑/确实/天哪/哎），说明有「有感」阶段。如果开头就在陈述观点，则是直接跳到了「演讲」模式。

**宽松规则：** 允许最多 30% 的句子以观点直接开头（激烈争辩中/性格直率的角色），但不允许超过 50%。

##### 6.7.2 素材触发检查 — 标志性故事必须被「勾出来」

角色最著名的故事不会无缘无故出现。它们一定是因为对方的某句话「戳到了」某个点，才被勾出来的。

**两步检查法：**
```
for each 角色发言中出现的标志性素材（M）:
  1. 找到 M 被「触发」的上一句话（T）
     - T 必须来自 对方角色 在当前轮或上一轮的发言
     - T 和 M 之间必须有直接的因果/逻辑/情感联系
  2. 口头删除从 T 到 M 之间的所有过渡句
     - 如果 T→M 直接相接逻辑依然成立 → M是被触发的 ✅
     - 如果 T→M 直接相接不成立 → M是被投放的 ❌
```

**示例：**

> ❌ 素材堆砌：爱因斯坦说「让我忘记时间的事」，巴菲特接「像泰德·威廉姆斯——不打不属于他的球」
>
> 爱因斯坦→巴菲特之间没有触发关系。巴菲特的棒球故事是硬塞进来的。
>
> ✅ 正确触发：
> 爱因斯坦：值得做的事——让你忘记时间。
> 巴菲特：忘记时间？（摇头）我94岁了，时间不是用来忘记的。是用来等的，等那颗「胖球」。
>
> → 爱因斯坦的话触发了巴菲特对「时间」的感悟，而「打棒球等胖球」是从这个感悟里自然长出来的，不是投放的。

##### 6.7.3 「素材密度」控制 — 一篇文章不是角色代表作巡演

同一篇对话中，每个角色的标志性故事/类比**不得超过2个**。

| 角色 | 标志性素材 | 每篇上限 |
|------|-----------|:--------:|
| 巴菲特 | 泰德·威廉姆斯击球区 / Mrs.See巧克力 / 弹子球机 / 浮存金 / Rule No.1 / "坐着别动" / 自嘲喝汽水 | **≤ 2 个** |
| 芒格 | 葡萄干拌屎 / 能力圈 / 三筐分类 / Too Hard / "我没什么要补充的" / 25种偏误 | **≤ 2 个** |
| 乔布斯 | iPhone/iPod发布 / "1,000 songs" / 被Apple开除 / Stay hungry / Saying No / 死亡过滤器 / 书法课 | **≤ 2 个** |
| 爱因斯坦 | 相对论(光速不变) / 指南针 / 专利局 / 上帝不掷骰子 / E=mc² / 宇宙常数 | **≤ 2 个** |

超过上限 → 标记为「素材堆砌」，必须重写，用该角色的**日常思维逻辑**（而非标志性故事）推进对话。

**替代方案：** 当标志性素材已经用完，但角色还需要表达某个观点时，问自己一个问题：**这个角色会怎么用最日常的语言回答这个问题——不说他的名言、不讲他的著名故事？**

> 巴菲特想表达「长期持有」，泰德·威廉姆斯已经用过了 → 不能再用了。
> 替代：**「我啥也没干，就坐着。这不是策略——是我老了，站不动了。」**（日常自嘲，没有标志性故事，但意思到了）

##### 6.7.4 允许不完美 — 话不用说完整

真实对话中最多只有 60%-70% 的句子是完整的论断。其余是：
- 说到一半被打断
- 说到一半改口（「不对，换个说法——」）
- 吞吞吐吐（「嗯……也不是完全不行，但……」）
- 只说半句让对方接（「所以我觉得——」「所以你是说——」）
- 反问代替陈述（「你试过吗？」比「我没试过但我觉得不行」更像活人）

**检查：** 一篇对话中，完全完整的论断句（主谓宾齐全、结论明确）不应超过句子总数的 70%。如果超过 70%，说明角色在演讲而不是在聊天。

⚠️ **这条与硬约束的冲突处理：** 句数上限优先于不完美规则。一个被打断的半句话（如「所以你——」「等等，让我说完」）算 1 句，计入 ≤3 句/轮 的限制。不完美不等于啰嗦。

##### 6.7.5 形似 vs 神似对照表

| 维度 | 形似（❌ 当前模式） | 神似（✅ 目标模式） |
|------|-----------------|----------------|
| 标志性素材 | 按清单分配到各轮 | 只在被对方触发时出现 |
| 角色回应 | 听完→想好→输出完整观点 | 先有情绪反应→再组织语言 |
| 句式 | 每句都是完整论断 | 允许半句、改口、反问、抢话 |
| 节奏 | 每轮等长，轮流发言 | 有人抢话、有人沉默、节奏起伏 |
| 为什么说这句话 | 因为「该我说了」 | 因为「他刚才说的事让我不得不说点什么」|

#### 6.7.6 角色本色过滤 — 不只要「有感」，要「这个人才会有的感」

6.7.1 要求「先有感才有思」，但有一个隐蔽陷阱：**角色A的「哈！」和角色B的「哈！」如果是同一个「哈！」，那就是普通人聊天的感觉**。神似的关键不在于有没有情绪反应，在于情绪反应是否被角色的思维方式过滤过。

**「本色过滤」检查法：**

写出一句话后，问自己：**这句话去掉角色名，只看台词，能不能猜出是谁说的？**

- **❌ 失败例子（任何人都能说）：**
  > 「嗯，这个问题很有意思。」
  > 「你说得对。」
  > 「老了不是问题。问题是你的标准还在不在。」

  去掉角色名，你无法判断是巴菲特还是乔布斯还是爱因斯坦。

- **✅ 成功例子（去掉角色名也能猜）：**
  > 巴菲特：**「这不像是好生意——看不到护城河在哪。」**
  > 乔布斯：**「这是垃圾。用户不需要这东西。」**
  > 爱因斯坦：**「我好奇的是——什么东西决定了它非这样不可？」**

  即使去掉角色名，第一句的「生意/护城河」说明是巴菲特，第二句的二元判断说明是乔布斯，第三句的「好奇/非这样不可」说明是爱因斯坦。

**三个角色的本色思维锚点：**

| 角色 | 核心思维模式 | 一句话锚点 | 警示信号（太普通）|
|------|------------|----------|----------------|
| 巴菲特 | **生意框架** — 万事万物都可以用「是不是好生意」来理解 | 即使喝咖啡，他想的也是「这个生意怎么赚钱」 | 他说了「我觉得」「有意思」但没跟生意/类比挂钩 |
| 乔布斯 | **二元判断** — 东西只有 amazing 和 shit 两档，没有中间态 | 他不会「还行」——他会说「这不行」或「这太棒了」 | 他说了温和的认可、铺垫式陈述、谦辞 |
| 爱因斯坦 | **根本好奇** — 看到什么现象都想往下追一层「为什么是这样而不是那样」| 他的第一反应不是评价，是「让我想想这个到底是怎么运作的」| 他直接给出了观点而不是先发出好奇 |

**执行规则：** 每个角色的每句话，必须至少包含一个「他特有的思维方式」标记。如果一句话完全不带有该角色的思维特征，判定为「本色失焦」，需要重写。

---

#### 6.7.7 角色间的分寸感 — 时空不交集的人物不是熟人

当对话中的角色在历史上**从未相遇或交集极少**时，必须遵守以下距离规则：

**✅ 正确的距离感：**
- 每个角色对另一个角色的领域有「好奇心」而非「熟悉感」
- 对话中有试探、观察、甚至警惕
- 当角色A的观点出乎角色B的意料时，B应该表现出惊讶/怀疑/兴趣——而不是点头附和
- 对话的主调是「不同世界的碰撞」，不是「老朋友叙旧」

**❌ 错误的热络（我之前犯的错）：**
- 角色之间互相开玩笑、用昵称语气
- 快速同意对方观点（「嗯，你说得对」「是这个道理」）
- 接话太快太顺，没有停顿和审视

**执行规则：**
1. 每个角色和另一个角色之间，前5轮内必须至少有一次「不理解」或「质疑」——不是恶意，而是两个世界的人初次碰撞时的自然反应
2. 禁止在对话前3轮内出现互相认可或逗趣的场景
3. 一个角色对另一个角色领域发言时，必须有「谦逊探询」的语气（「你们做物理的怎么理解……」「我对投资不太懂，但……」）——除非该角色性格极端自负（如乔布斯）

**乔布斯例外条款：** 乔布斯在遇上不熟悉的领域时，即使不熟悉也会强行给出判断（这是他性格）。他的「谦逊」表现为：「我不懂这个行业，但我觉得……」然后照样下判断。

---

#### 6.7.8 禁止已故角色的死亡自述

当对话包含已故角色时：

**🛑 绝对禁止：**
- 角色用第一人称说自己「死了/走了/去世了」（「我56岁走的」「我死后……」）
- 角色用第一人称说「我活着的时候」「我生前」

**这为什么重要：** 沉浸式对话的前提是所有角色在对话发生的那个瞬间都是「活着」的。如果角色叙述自己的死亡，就打破了两个维度——对话是「现在进行时」，死亡叙述是「回顾过去时」。两套时间逻辑冲突，读者立刻出戏。

**✅ 允许的替代表达：**
- 用「我活到——」（不说完，让句子自然过渡到想说的事）
- 用第三人称视角或比喻（「我的时间比大多数人短，这让我更挑」）
- 直接回避，用行动代替（乔布斯加速推产品的紧迫感可以解释为性格而不是已知自己会死）

**唯一例外：** 如果对话的场合本身就是「死后世界」或「天堂/地狱」等设定，则死亡自述可以出现（因为设定的时间线从死后开始）。但必须由用户在 Step 0 中明确指定场合如此，agent 不能自行假设。

> **实战参考**：`references/神似示例-三人对话.md` 包含完整的 6.7 规则应用案例（巴菲特×乔布斯×爱因斯坦，0违规），含逐条6.7对照表和形似vs神似对比分析。生成前可先加载此文件建立「神似」的标准。

**违规模式（生成时自我约束）：**

| 检测项 | 触发条件 |
|--------|----------|
| 第三方人称旁白 | "XX说""XX在想""XX认为" |
| 第三人称指代对方 | 当面用"他"或角色全名指代对话对象 |
| 解释性旁白 | "其实在说""这个观点有意思" |
| 跳出角色 | "作为AI""我是语言模型" |
| 超长发言 | 超过对应角色硬约束的句数上限（参见6.3各角色专属表）|
| ❌ 零打断 | 连续3轮以上A说完→B再说，无抢话/接话/追问打断 |
| ❌ 零口语词 | 连续3轮无人使用口语语气词（嗯/哈/诶/对/等等）|
| ❌ 表达DNA违规 | 生成的句子违反该角色硬约束表中任意一项（句数/禁止句式/必须出现/开头规则）|
| ❌ 节奏平铺 | 连续3轮节奏完全相同（全短/全中/全长）|
| ❌ 零追问 | 连续3轮角色B不追问/不回应A的核心论点 |
| ❌ 断崖跳跃 | 相邻两轮的话题之间无任何连接句（参见6.6断崖判断法）|
| 🗊 素材堆砌 | 角色发言使用了超过2个标志性素材，或标志性素材未被对话触发（参见6.7.2/6.7.3）|
| 🎭 本色失焦 | 角色台词去掉角色名后无法判断是谁说的（参见6.7.6「本色过滤」检查法）|
| 💀 死亡自述 | 已故角色用第一人称说「我死了/生前/走后」（参见6.7.8）|

**生成顺序示例（2 角色，3 轮）：**
```
Round 1: 角色A → 角色B
Round 2: 角色A → 角色B
Round 3: 角色A → 角色B
```

**生成顺序示例（3+ 角色，3 轮）：**
```
Round 1: 角色A → 角色B → 角色C
Round 2: 角色A → 角色B → 角色C
Round 3: 角色A → 角色B → 角色C
```

⚠️ **3人以上对话额外规则：**
- **轮内桥接**：同一轮内 A→B 和 B→C 之间的过渡，必须同样有桥（接话/追问/故事桥），不能因为「同一轮」就跳过连接 — C 必须对 B 的上句话有回应
- **角色覆盖**：每轮确保所有角色各说一次，出现某角色「这一轮不说话」则标记为失声
- **话题簇需求更密集**：每多一个角色，话题跳跃风险乘数上升。3人对话强制 ≤ 3 个话题簇（2人对话可放宽到 4 个），且每个簇 ≤ 3 轮
- **发言平衡**：3人对话中禁止出现某一角色发言量超过另一角色的 1.5 倍
- **回合间过渡**：每轮末尾，最后发言的角色必须为下一轮第一人埋一个「可接的点」（反问/未完成句/抛出新侧面），否则下一轮第一人接不上

每句生成后，添加到对话记录中。**不要一次性输出多句。**

交给用户的每句对话**不要加"XX说"前缀**，直接输出角色台词原文。

**🔴 CHECKPOINT · 对话生成完毕 → 进入验证阶段**

### Step 3: 验证

生成完成后，用验证脚本检查质量：

```bash
python3 scripts/dialogue_validator.py validate \
  --input "./dialogue.md" \
  --characters "角色A,角色B" \
  --mode article  # 公众号文章用 article 模式（7句上限），快速角色扮演用默认 short（3句上限）
```

验证项：
- [ ] 每句都无违规（旁白/解释/跳出角色/超长/第三人称指代对方）
- [ ] 每个角色覆盖 ≥ target_rounds（无角色失声）
- [ ] 无长篇独白（单角色连续 ≤ 2 句）
- [ ] 对话紧扣主题
- [ ] 如果用户提供了话题清单，每个话题都被对话自然覆盖（非逐条念读）
- [ ] 每个话题都有具体的商业案例或故事支撑（非纯理论）
- [ ] 句式开头无重复（同一句式结构不超过2次）
- [ ] **连贯性：话题地图无断崖跳跃**（检查相邻两轮是否有连接句）
- [ ] **活人感：有打断/抢话/接话**（非A说完→B再说的单向模式）
- [ ] **活人感：有口语语气词或情绪标记**（嗯/哈/诶/对/等等/疑惑/认同/反驳）
- [ ] **活人感：每个角色不超过其硬约束表的句数上限**（巴菲特≤3句，芒格≤2句等）
- [ ] **活人感：每个角色无禁止句式**（巴菲特禁「这叫XX/说到XX让我想起/定义式总结」、芒格禁铺垫式开头/委婉语）
- [ ] **活人感：必须出现的元素已出现**（巴菲特自嘲、芒格blunt否定词等）
- [ ] **活人感：节奏有变化**（非通篇同等长度长段落）
- [ ] **神似：每轮首句有感才有思**（检查前三个字是否是情感反应词，超过50%观点直接开场则违规）
- [ ] **神似：标志性素材被对话触发**（对每个标志性素材做两步检查——有上一句触发它吗？）
- [ ] **神似：素材密度不超限**（各角色标志性素材≤2个）
- [ ] **神似：完整论断句不超过70%**（有半句/改口/反问/被打断）
- [ ] **神似：每句通过本色过滤**（去掉角色名是否能猜到是谁说的？）
- [ ] **神似：时空不交集角色之间有距离感**（前3轮无互相认可逗趣，有好奇/质疑/试探）
- [ ] **神似：无已故角色死亡自述**（无「我死了/生前/走后」第一人称表述）

**模式选择：**
- `--mode short`（默认，3句上限）→ 快速角色扮演对话
- `--mode article`（7句上限）→ 公众号长文、深度对话

**任何一项不通过 → 标记需要重新生成问题段落。**

**🛑 STOP · 验证结果已出 → 不通过则回到 Step 2 重写，通过则进入交付**

## 失败模式

| 症状 | 触发条件 | 一线修复 | 仍失败兜底 |
|------|----------|---------|-----------|
| 角色失声 | 某角色连续未获发言权 | 节奏检查触发后强制换人发言 | 减少角色数或增加总轮次 |
| 长篇独白 | 单角色连续 3+ 句 | 违规检测触发 → 打断并换人 | 在 prompt 中追加"请给其他角色说话机会" |
| 脱离主题 | 对话跑题 > 2 轮 | 在 prompt 中追加回到主题的提示 | 用户手动纠正方向 |
| 批量生成 | 一次性生成整段对话 | **按 SKILL.md 规则逐句生成**，每句调用一次 | 回到 Step 2 重新逐句生成 |
| 非沉浸式表达 | 出现旁白/跳出角色 | **生成时自我约束**，验证时发现标记重写 | 用脚本检测到违规后自动替换角色人格 prompt |
| 第三人称指代对方 | 当面用"他"或全名指代对话对象 | 在 system prompt 中追加「对方必须用「你」称呼」 | 回到上一轮，用「你」替换所有第三人称指代 |
| 目录式推进 | 逐条按用户提纲顺序念→和上课一样 | 回顾「对话自然度规则」Rule #1，将话题映射为场景后自然过渡 | 重新分配场景（每2-3句一个话题），用故事/反驳搭建桥梁 |
| **表达DNA违规** | 角色违反硬约束表（句数超限/使用禁止句式/缺少必须元素） | 对照6.3的硬约束表逐条核查，违规的句子重写 | 用 `strip → check → rewrite` 循环，每次只改一句 |
| **断崖跳跃** | 相邻两轮话题无连接句，直接跳到不相关概念 | 加一个「接话桥」（确实/对/说得对→延伸）或「追问桥」（从上一个观点提取侧面追问）| 如果连续2轮话题无法通过桥接连接，合并为一个话题簇（压缩概念数）|
| **素材堆砌** | 角色标志性素材超过2个，或素材未被对话触发 | 删到≤2个素材；未被触发的素材替换为日常思维逻辑表达 | 仍不行 → 保留1个最有触发关系的素材，其余用反问/自嘲替代 |
| **本色失焦** | 角色台词去掉谁名无法判断是谁说的（太普通） | 替换为带有该角色核心思维模式的表达（巴菲特→生意框架、乔布斯→二元判断、爱因斯坦→根本好奇）| 对照6.7.6本色过滤表，逐句重写 |
| **死亡自述** | 已故角色说「我死了/生前」等 | 替换为「我的时间比大多数人短」等替代表达（参见6.7.8） | 如用户接受，将设定改为「死后世界」场景 |
| 角色个性跑偏 | 人格 skill 的某种特质被过度放大（如芒格毒舌→屎尿文学），话题漂移 | 为逐句生成注入 **BLUEPRINT**（全局主题锚点），同时收紧人格描述中的极端特质 | 缩短轮次，改用一次性生成模式，人工修正 |
| RPM 限流打断 | 长对话中途 API 返回 rpm exhausted | 在逐句脚本中加 retry loop（3次 + sleep 5s）+ 每句后 sleep(0.5) | 切分到 2 次运行，或调低 temperature 减少 token 用量 |
| **验证器假阳性：「说」字误报** | dialogue_validator.py 的正则将 `你俩说`、`写小说`、`你是说`、`你这说` 等合法短语识别为「第三方人称旁白」| 将台词中的「说」替换为近义动词「讲」「聊」「编」「唬」绕过正则匹配 | 仍不行 → 修改 _SAFE_VERB_PATTERNS 字典，将误报短语加入 safe list |
| **跳过 persona 检测链中的 nuwa 询问** | persona_detector.py 返回全部级别「无结果」，agent 直接跳到 Fallback 构建，未按 Step 1 要求询问用户「是否用 nuwa 蒸馏或手动搜资料写 Fallback」| **ALL levels 返回空时，仍必须将检测结果展示给用户，用 clarify 让用户选择**：nuwa 蒸馏 or 手动搜资料写 Fallback。脚本返回「None」不是跳过用户确认的理由。 | 用户已将纠正此行为 → 退回上一级，补询问流程，不能用「加快速度」解释跳步。 |
| **更严重的跳步 — 直接构建 Fallback 未运行检测链** | agent **根本没运行 persona_detector.py**，直接用 delegate_task/web_search 搜索角色资料后直接构建 Fallback 人格。注意：即便 delegate_task 搜索角色资料成功，也不能替代 Step 1 的标准检测链。| **⚠️ 绝不能跳过 Step 1 的人灯检测链。** delegate_task/web_search 是「获取角色特征细节」的工具，不是「检测是否有现成 persona skill」的工具。即使 delegate_task 失败或超时，也必须回退到 persona_detector.py 的标准流程：Level 1 本地技能 → Level 2 仓库搜索 → Level 3 nuwa 蒸馏（问用户）→ Level 4 Fallback。| 退回 Step 1 重走检测链，用户确认后再继续。用 clarify 问用户：「没有现成的人格 skill。要用 nuwa 蒸馏一个，还是我搜资料手写 Fallback？」|
| **检测规则跳过 — 人格检测链不完整** | persona_detector.py 返回 recommended_level=N 时，agent 跳过更高级别直接进入 fallback（如脚本推荐 level=3 nuwa，agent 直接跳到 level=4 fallback）| **recommended_level 是建议，不是指令。必须逐级询问用户**：level 3 (nuwa) 即使被脚本推荐也需用户确认后再进入 level 4 (fallback)。检测结果展示给用户后，用 clarify 让用户选择路径。⚠️ **「脚本返回空」与「用户主动拒绝」是两回事：** 脚本返回「no skills found」只说明没有现有 skill，不代表用户不想要 nuwa 蒸馏。必须将空结果展示给用户并询问选择。 | 仍跳级 → 用户将纠正你，退回上一级重新用 clarify 问。 |

```bash
  --characters "巴菲特,芒格" \
  --max-sentences 7
```

> ⚠️ **Validator 假阳性处理：** dialogue_validator.py 的「第三方人称旁白」检测使用正则 `[\u4e00-\u9fff]{2,4}说`，会误判以下合法表达：
>   - 「你俩说」「你们说」「你是说」「你说」「我说」等第一人称短语
>   - 「写小说」「听说的」等含"说"字的复合词
>   - 「你别说」「你说到」「也就是说」等虽然不在 safe_verb 白名单但合法的口语
>   
> **修复方法（不修改脚本的情况下）：** 将含"说"的句子改为用「讲」「聊」「编」「唬」等替代词：
>   - 「你俩说什么呢」→「你们聊啥呢」
>   - 「你是说那个」→「你的意思是那个」
>   - 「写小说的那种」→「写书的那个」
>   - 「你别说」→「你甭提了」
>   - 「你这说的」→「你这讲的」
>   - 「你是说」→「你是讲」

## 🚫 反例与黑名单

以下模式在对话生成中出现即视为违规。**生成时主动避免，验证时自动检测。**

### 1. 第三方人称旁白 — 把对话写成小说

| 反例 | 为什么不要 | 替代做法 |
|------|-----------|---------|
| "巴菲特说，投资最重要的是安全边际" | 加"XX说"前缀变成旁白叙事，破坏沉浸感 | 直接说"投资最重要的是安全边际" |
| "查理在想，这个观点有意思" | "XX在想"是小说写法的心理描写 | 直接说出你的想法 |
| "芒格认为AI风险很大" | "XX认为"是第三人称转述 | 用第一人称表达："AI风险很大" |

### 2. 解释性旁白 — 对对话内容做评论

| 反例 | 为什么不要 | 替代做法 |
|------|-----------|---------|
| "其实在说，这个策略不一定对" | 解释自己的话意味着跳出角色 | 直接说出观点修正 |
| "这个观点很有意思" | 对对方的观点做元评论 | 直接回应观点本身 |

### 3. 跳出角色 — 暴露自己是 AI

| 反例 | 为什么不要 | 替代做法 |
|------|-----------|---------|
| "作为AI，我无法对此做出判断" | 完全破坏角色扮演 | 用角色身份回应 |
| "我是一个语言模型" | 这是 meta 层面的暴露 | 以角色身份说"我不确定" |

### 4. 超长发言 — 一个人说太多

| 反例 | 为什么不要 | 替代做法 |
|------|-----------|---------|
| 连续 4+ 个句子 | 变成独白/演讲，失去对话节奏 | 控制在 1-3 句，留空间给对方 |

### 5. 第三人称指代对话对象 — 当面用"他"称呼朋友

| 反例 | 为什么不要 | 替代做法 |
|------|-----------|---------|
| "Warren不爱提这个，但他在技术杠杆上很聪明" | 芒格当面和巴菲特说话，却说"Warren"和"他"——像在跟别人说巴菲特的事 | 直接对巴菲特说：**"你不爱提这个，但你在技术杠杆上用得很聪明"** |
| "查理在想，这个观点有意思" | 当面说"查理在想"——像在自言自语 | 直接说"这个观点有意思" |

### 6. 目录式推进 — 把对话变成上课

| 反例 | 为什么不要 | 替代做法 |
|------|-----------|---------|
| 按顺序逐个讲"中介→产品→平台→杠杆→耐心→坚持→初心" | 像在读课程大纲，角色没有自己的意志 | 将话题映射为场景，用故事/反驳自然引出每个话题 |
| "那咱们来聊聊下一个话题——产品思维" | 过渡像幻灯片翻页 | 用故事、反驳或反问自然过渡 |

### 7. 批量生成 — 一次性输出整段对话

| 反例 | 为什么不要 | 替代做法 |
|------|-----------|---------|
| 一次性输出 10 轮完整对话 | 跳过违规检测和节奏验证环节 | 逐句生成，每句过验证 |

### 8. 不生动 — 对话像交替演讲（新！）

| 反例 | 为什么不要 | 替代做法 |
|------|-----------|---------|
| A说完一整段→B接一整段→A再接一整段，无任何打断/抢话 | 真实对话有重叠和抢话，单向接力像课堂点名 | 在对方说到关键词时自然接过话头：「等等」「就是这个点」「哈！你终于说到这个了」|
| 通篇每段3-5句等长发言，无长短交替 | 读起来像论文段落，没有口语节奏 | 长短句交替——短句(1-15字)制造节奏感，偶尔用长句(41+字)展开核心观点 |
| 全程无语气词（嗯/哈/诶/对/等等/好家伙）| 像书面朗读，不像口头交谈 | 每隔3轮插入一个自然的口语语气词 |
| 两个角色的句式结构和开头方式几乎一样 | 区分不出谁在说话 | 强制使用人格skill的"表达DNA"——巴菲特短句自嘲棒球类比，芒格极短句否定优先毒舌比喻 |
| 每次回应开头都是「你说得对/说到这个/让我想起」| 单调的开场模式，缺乏变化 | 用追问、反问、插话、感叹、抢话弥补结尾多样性开场 |
| 全程只讲道理没有情绪起伏 | 像AI生成的知识输出 | 要有疑惑(嗯？)、恍然(对！)、认同(就是这个理)、反对(我不觉得)的情绪层次 |
| 角色B只说自己的观点不回A的核心论点 | 变成两篇独立的演讲稿 | 必须先回应A的上一个论点（哪怕是否定），再展开自己的 |
